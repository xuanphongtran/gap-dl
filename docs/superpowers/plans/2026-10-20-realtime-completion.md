**Goal:** Complete typed lifecycle reconciliation and safe room presence/typing using the existing workspace socket, with local protocol and browser acceptance.

**Architecture:** Keep the existing VueUse connection and REST recovery owner. Add a focused room-activity owner for ephemeral state, deadlines and typing input; expose readonly activity through the existing injected context. ## Review Focus

1. Another tab of the same user joins while this socket is not subscribed: its join must never unlock typing on this socket (Tasks 3/4).
2. A presence HTTP response predates a later typing stop, leave or revocation: late snapshot data must not restore activity (Tasks 3/4).
3. A lifecycle update concerns a retained older page, including a deleted uploader: reconcile revision/tombstone/files without requiring reconnect or showing erased metadata (Task 2).
4. Programmatic draft restoration, IME input, Search hiding, pending send and rapid room/account changes: only live editable user input sends typing, and an old stop never reaches a replacement socket/account (Tasks 3–5).
5. Fixture creation or cleanup loses a response, or the runner exits after creating an owner: durable journal uncertainty and intentional retention remain distinct, reusable and accurately reported (Tasks 1/6).

## Task 3: Implement isolated room activity and typing scheduling

**Files:** Create `src/features/rooms/useRoomActivity.ts` and `.test.ts`.

**Interfaces:**
- `useRoomActivity({isCurrent:(scope:RoomActivityScope)=>boolean,send:(scope:RoomActivityScope,command:RoomTypingCommand)=>boolean})` returns `{state,activate(scope),pause(),receive(scope,event:RoomActivityEvent),invalidate(scope),input(hasText:boolean),stop(),refresh():Promise<void>}`. `state` is readonly `Ref<RoomActivityState>`; no exposed timer, token or frame. Disposal is scope-owned.
- `activate` clears prior state, increments a private generation and aborts reads; only a matching valid WS snapshot confirms subscription. `refresh` obtains safe server data via Vue Query/signal/current scope; HTTP alone cannot authorize typing. `pause` immediately clears IDs/confirmation/timers and invalidates late work. `receive` accepts only current scope; presence and typing update sets without durable queries.
- HTTP snapshots never create initial subscription confirmation or enable unverified activity UI; apply repair data only after this connection has received a valid snapshot. Snapshot fetch captures both generation and local event version; never apply a response older than any intervening activity transition. Failed reads mark activity unavailable without room revocation. Repair reads coalesce and run at most once/2000ms, respect absolute Retry-After deadlines, retry:false and no automatic write replay.
